# Run 5 — full synthesis (plan only)

Status: **not built**. The four Superrooms belong to the current review cycle after Run 4. Their feedback should inform Run 5 before construction begins.

## Recommendation

Split Run 5 into **5A: four compact rooms (two per side)** and **5B: four continuous superrooms (two per side)**, with a review between them. Do not commit to eight ideas before the first four work. Keep only ideas with a distinct discovery; reduce or replace the batch if ideas repeat the bank. A later optional 5C can refine campaign placement and difficulty variants, rather than automatically creating more rooms.

Run 5's purpose remains the original one: synthesize old and new movement, entities, combat and spatial puzzles. A new mechanic is not a quota. A strong interaction earns its inclusion by changing the player's decisions.

## Lessons to preserve

- **The Useful Ceiling / Umbrella Exchange / Return Freight / The Weight Must Stay:** geometry and an object's changing job create the puzzle. Carrying, leaving and recovering an object should have different consequences.
- **F33:** preserve a creative player solution when it is more interesting than the preview. Its parry, retreat and wavedash route became the intended route; the aim is a good central problem, not obedience to one tape.
- **B43 and F42:** a cargo route can prepare a later movement transfer. Collection, shade and momentum should interact rather than occupy separate tutorial stations.
- **F31/F32 and the echo launch feedback:** readable intention is insufficient when execution has a tiny success window. Broaden contact and landing space before adding another required action. Fractured should ask for a harder decision or richer chain, not an unreliable catch.
- **B41/B42:** an attractive mechanic demonstration is not a full puzzle. Direct swing and overhead routes must be considered at the sketch stage. If the obvious bypass removes the whole problem, redesign the problem before adding spikes.
- **F35:** do not remove the premise while making a room forgiving. The useful range of recoil must matter. A controlled short jump that still manages lift can be a valid alternate solution.
- **B40/F41/F44 transfers:** classify by the human experience, not the ID or the engine feature used. Current side assignments reflect the user's judgments; numeric ratings remain unmeasured.

## 5A — discover four strong interactions

These are design questions, not approved layouts or required mechanics.

| Candidate direction | Shared decision | Possible ingredients | Distinction to test |
| --- | --- | --- | --- |
| Base: choose what stays | Leave a useful object to hold a route, then recover it from the other side when that route is no longer needed. | Lantern, plate, hinge, timed cover or moving support | Does abandoning the useful object feel like a discovery rather than a fetch errand? |
| Base: make the return possible | The outward crossing changes a familiar piece of geometry that becomes the return foothold or shelter. | Blade, rotating door/hinge, recoil lift, modest environmental timing | Is the later route visibly caused by the player's earlier choice? |
| Fractured: spend the launch twice | Build and redirect movement so the transfer also positions cargo or an echo for a second use. | Reverse launch or wallbounce, moving hook, echo, cargo catch | Does each transfer change the next choice, without depending on a near-frame-perfect final catch? |
| Fractured: keep the dangerous helper | A hazard or enemy is useful until a particular moment; destroying or disabling it too early changes the route. | Pogo/parry, moving solid, beam, seed or breakable support | Is this a spatial puzzle with active traversal, rather than combat followed by a jump? |

Choose from these after comparing them with the entire bank and the Superrooms. Write the discovery and nearest existing room before drawing the map. Reject proposals whose novelty is only a longer gap, narrower landing, added spike or renamed switch.

Each room should contain a discovery, a consequential manipulation and a satisfying execution. This is a design guide, not three isolated zones. Ordinary timing rests are useful when they let the player read the next moving obstacle. Avoid long compulsory waits after a solved step.

## 5B — build continuous rooms around approved discoveries

Choose the strongest 5A ideas plus existing approvals. Do not paste their maps together. Redraw the architecture around one or two persistent objects or shared pieces of geometry.

Each superroom should have:

1. A visible destination or obstruction that establishes the larger problem early.
2. At least three normal room areas with substantial travel through them; padding does not count.
3. A route that crosses, returns above/below, or revisits a previous space with changed state.
4. An earlier choice that affects at least two later uses of the same object or structure.
5. Safe places to read timing cues, followed by purposeful movement between them.
6. A final action that resolves the shared problem, not a harder isolated jump appended at the end.

Use the current four Superrooms to decide whether this size improves play. A short room with one excellent discovery is preferable to a sprawling room with filler. Base can use several interacting systems while retaining generous contact windows. Fractured can demand momentum planning, deliberate resource use and more demanding transfers; its essential timing still needs to be readable and reproducible.

Do not add checkpoint infrastructure merely to justify making rooms longer. If testers enjoy the puzzle but dislike repeating the solved opening, compare a shorter layout against a visible checkpoint that restores the correct room state. Treat any checkpoint implementation as separate scoped work.

## Acceptance and focused checks

Save each room immediately after its first draft, and again whenever geometry or the solution changes. Record stable ID, intended discovery, nearest existing room, shared dependencies, estimated placement and a complete route.

Before human review, check one clean completion; the obvious direct jump/dash/climb/swing bypasses; any shortcut reported by the user; and a few early/late inputs around the hardest mandatory transfer. Check real browser scrolling and that the player can see the relevant landing or cue. Stop once the evidence addresses those risks. Do not search for every possible alternate solution or make testing the project itself.

For a bypass that retains the main decision and is fun, keep it and update the preview. For a bypass that erases the main decision, change visible geometry or the causal puzzle. Never require hidden proof that a named action was performed.

## Review and placement

Use the existing Fun /10, Difficulty /5 and Suitability /5 forms, including unfinished attempts. Ask testers to use the optional note for unclear cues, excessive repetition, unreliable catches and alternate routes. Track an inability to finish separately from a missing rating; it is evidence, not a reason to discard the response.

After several people review the same revisions, inspect difficulty distributions separately for Base and Fractured and separately for compact rooms and superrooms. Compare median difficulty and disagreement alongside fun, suitability, deaths and completion, where available. Do not force a bell curve or equate a longer room with a harder room. Choose campaign slots from the intended progression and observed results, then keep easier/harder variants as reserves only where they add useful coverage.

Start 5B only after the 5A feedback identifies ideas worth expanding. Begin a distributed full playtest only after revisions, bank classifications and the chosen review build are stable. No Run 5 rooms are authorized or generated as part of this planning document.
