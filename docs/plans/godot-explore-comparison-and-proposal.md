# Explore native draft: comparison and proposed revision

2026-10-24. Baseline: native draft `e0ac32b`, browser source `8b42d81` (7.379.0). This document changes no Explore runtime, artwork, data, recordings, or packaged app. The user's observed freezes and visual dissatisfaction are requirements to investigate, not disproved by the draft's passing route tests.

## Confirmed regressions raised in the feedback

| Area | Browser game | Native draft | Evidence / consequence |
|---|---|---|---|
| Locked dash | `lockedMovementFeedback()` records a diagnostic and explicitly emits no lore text, HUD, or error sound. | Every fresh dash press calls `cue("A dash memory is missing")`. | `public/index.html:1278`, native `world.gd:230`. The user is right: the native text is an added behavior. A phrase in an older capability table does not justify displaying it. |
| Surviving a fall | In ordinary solo play, records grounded `safeTrail` samples every 0.15 seconds; surviving a pit/hazard rewinds to an earlier local safe point, roughly half a second before the edge. Fatal falls use death recovery. Watch/bots/co-op have separate recovery rules. | `p.y < -180` calls `die()` regardless of remaining blood. Retry uses a checkpoint or regional start and fills five blood. There is no safe-ground trail. | Browser `hurtPlayer()` around 14769 and trail sampling around 18763; native `world.gd:140–190,340`. This loses the local recovery loop and turns a survivable mistake into a large replay. |
| Knight identity | The established blue character, equipment silhouettes and animations are drawn by `drawHero` / the respec renderer. | A separately invented silver-armored character, pale plume, gray cape, broad shoulders and helmet; art extends well above the 44-unit collision body. | Native `landscape.gd:542`. Reusing collision dimensions does not preserve the character design. |
| Visual identity | Region-specific renderer, landmark art, resident designs and work routines, forest silhouettes, existing materials and composition. | A new procedural renderer: repeated block towers, generic triangular foliage, simpler rectangles for people and props, gray stone and subdued lighting. | Native `landscape.gd`, compared with `bladefall-respec-renderer.js` and `bladefall-resident-art.js`. Native lighting and particles do not compensate for replacing the visual language. |
| “Freezing” during play | Explicit conversations also pause gameplay using `mode='conversation'`, with framed dialogue, portraits and conversation controls. | `_physics_process` returns whenever `audio.talking()` is true. These are confirmed intentional stalls/input gates, plausible contributors to the report. They do **not** establish that every reported freeze has this cause. |

## Other differences, including within the two imported regions

The imported maps and recordings are content inputs. The native code is a new implementation of Explore, not the browser engine running under Godot. Each row below names a difference or an unproven equivalence; a passing native route is not evidence that the browser behaves the same way.

| Surface | Difference and practical effect |
|---|---|
| Scope | Native contains Outskirts and Black Woods only, ending at the Causeway entrance. Base has the remaining main campaign, bosses, Fractured campaign and its progression. The native region selector is a prototype control rather than base Level Select. |
| Terrain | Authored object definitions are imported, but native `platform`, `top`, `floor_at` and wall collision interpret them independently. Slopes, edges, supporting platforms, one-way contact and moving geometry have no comprehensive browser/native comparison. Four flat movement traces do not cover these. |
| Movement | Native reproduces selected opening run/jump rules and hardcodes the 90% jump setting. It has no complete capability/unlock model or the browser's Assist configuration and later verbs (dash progression, wall/double jump, downward strike, gravity, portals, hook, echo, companion systems). Matching 741 flat-ground frames is narrow evidence only. |
| Combat | Native reimplements attack reach, up-strikes, cooldown, hit tests, knockback, invulnerability, shield flanking and enemies. Browser weapons, protection, status effects and combat progression are not carried over as a system. The thirteen imported encounters have native approximations of their behavior. |
| Enemies | Patrol, rush, sentry, feint, duelist, diver, stalker and root/spore behavior are handwritten native state machines and new drawings. They are not proven equivalent to source timing, terrain awareness, targeting, collision, damage or tells. Native route survival does not prove enemy fidelity or enjoyable combat. |
| Blood and equipment | Native uses five fixed blood measures, integer wounds and its own ward bank; base `bladefall-blood.js` computes severity, defense/protection and vitality-based maximum blood. Native's Oathblade and Mothsilk Mantle are specific implementations, without the full inventory, item/equipment/stat and upgrade systems. |
| Checkpoints | Native starts/enters regions with at least one flag, earns replacements through its kill rule, and retries with fixed healing. Base recovery is integrated with its checkpoint, blood, safe-trail, rest-site, boss, save and progression systems. Do not assume those rules match. |
| Rest | Native nearby rest sets blood to five and shows a cue. It does not implement the full browser recovery catalog, saved Continue, waystation state reconstruction, camera preservation and related UI. |
| Opening quest | Native Rowan's cart, brake, bell, carrying and drake use a dedicated integer quest state and fixed positions. Base opening-story state, travel/staging, progression effects, journal, persistence and dialogue conditions are broader. This is a recreation, not a shared implementation. |
| Mara | Native has a three-bearing survey and simplified two-region field chart. It lacks the browser's broader map/journal, campaign exploration and retained survey state. |
| Elsie | Native has a moth chase, hit-reset lantern carry, three distinct log swings, hand-in and moth flight. It uses dedicated native state, hardcoded points and its own timing/feedback; base quest-errands, side-story state and rewards are separate. Completing a native replay does not establish equivalent routes, difficulty, rewards or save behavior. |
| Other people | Native recognizes selected fixed NPC locations and short dialogue branches. Base resident art includes individual proportions, attire, facial presentation, seated poses, props and multi-beat working routines (Elsie's pot, Orra's watch, Pell's resin, Hale's shoulder, Bram's lamp). Generic native work poses omit much of this characterization. |
| Bram / forest traversal | Native lamp-following, canopy jumps and lamp placement are a rewritten helper flow. Original visibility, route interaction, companion recovery and behavior need comparison beyond native success. |
| Mechanisms | Counterweight, resin pods, timed thorns, poisonous flowers, false branches and crumbling footholds run native-specific handlers. Their complete input, hit, timing, retry and persistence semantics are not covered by the browser comparison. |
| Quest presentation | Native uses fixed HUD objectives, hints and a transient cue plus selected completion effects. Base has its own world prompts, directional quest pointers, journal tasks, persistent return cues, award staging and story framework. These are different layouts and state sources. |
| Conversation | Native queues existing speech with a simple bottom subtitle panel, advancing with Up/Jump. Base has portraits, speaker framing, typewriter/skip behavior and its own closure/input flow. Both can deliberately pause; native must communicate the pause and release gate clearly. |
| Audio | Native copies 141 existing files (68 speech clips), plays selected effects, music, ambience and fire and supplies four broad volume buses. Base has a larger sound bank, sound-mixer take selection and per-effect levels, resident work sounds/barks, weather/place sound rules, combat voices and settings. File identity proves reuse, not equivalent triggers or mix. |
| Camera / framing | Native uses its own easing and fixed 1280×736 composition within a 1280×832 window. Browser logic uses 1440×900 with its camera controller, zoom, region banners and framing. Object size, visible route ahead, vertical look, HUD placement and perceived movement differ. |
| Art scale / readability | Native internally renders a 640×368 viewport, with a 0.5 world scale and final enlargement. Thin outlines, small props and lighting are filtered through this different scale pipeline. The source's visual density, character-to-platform scale and crisp silhouette cannot be inferred from imported coordinates. |
| Lighting / backgrounds | Native adds real point lights, shadow occluders, GPU motes/embers, grading and mist. These are new presentation choices; dark silhouettes and repeated backgrounds can reduce visibility despite additional effects. One screenshot's FPS does not prove stable frame pacing. |
| Map | Native chart is a two-strip schematic of imported floors, rooms, flags and bearings. It is a new chart design and does not reproduce all browser map behavior or campaign information. |
| Save / reload | Native saves audio/display preferences only; quest/equipment/enemy/journey progress lives in memory until restart or quit. Browser campaign saves and Continue survive sessions, including quest/reward/progression/recovery state. |
| Restart | Native full restart discards the journey; retry preserves its chosen state and restores five blood. Browser restart, death, saved Continue and optional quest practice starts have distinct semantics. |
| Watch | Native Watch replays native-generated input recordings, not the browser's recordings. Native success validates its own route, not original-game fidelity. Watch/Take control and preview UI differ from the browser's test mode, record and campaign eligibility rules. |
| Controls | Selected opening keyboard defaults and named controller bindings are present. The native draft does not reproduce full rebinding, touch controls, mobile behavior, controller calibration or all action-context priorities. Hardware controller behavior remains untested. |
| Menus / settings | Native has a prototype pause/settings panel and basic display/audio choices. Base's Level Select, test mode, inventory, workshop entry, Assist controls, game progression and online UI are absent or replaced. |
| Optional later systems | Native has no shops/forge progression framework, later optional stories and rides, boss devices and arenas, achievements/leaderboards/feedback, multiplayer/PeerJS, Together or shared quest synchronization, editor/workshop/publishing/community levels, Android packaging, or browser service-worker/update workflow. These missing systems matter separately from the first-two-region regressions. |

## Freeze investigation: what is known and what still needs measurement

Confirmed from code: conversation stops physics; the subsequent held-input gate can also stop it. The base also pauses for conversations, so removing all pauses indiscriminately would not reproduce the base. First measure whether a reported stop coincides with speech, a gate, a menu, or neither.

There are also potentially expensive loops: `floor_at()` scans the obstacle list; enemies repeatedly query terrain; rendering and collision have their own scans. Shader/pipeline startup, audio resource loading and GPU particles are possible frame-time contributors. These are investigation targets, **not diagnosed causes**. The old 88-FPS capture is one observation and cannot rule out intermittent stalls. No CPU/GPU frame-time trace of the user's freeze has yet been captured.

Before any Explore implementation: record median, p95, p99 and worst frame time during a cold launch and a ten-minute normal route, with dialogue, first effects, resin, combat, canopy, falls and recovery. Log pause/gate/speech transitions separately from rendering and simulation time; inspect the longest stalls. Compare against the browser along the same route, on the same Mac, without recording overhead in the main timing run.

## Proposal only: make the first two worlds look, feel and play better

No new quests, geometry, voices or Explore changes are authorized by this document.

1. **Restore behavior and identity first.** Match the browser's default knight silhouette and palette, sprite proportions, weapon placement and animation poses. Implement its local surviving-fall recovery and silent locked actions. Preserve the existing region geometry and earned optional rewards. These changes address the concrete feedback before adding decoration.
2. **Make stops legible and remove accidental gates.** Keep deliberately paused conversations with a clear speaking state and current bound advance key. Consume the closing press without requiring unrelated held buttons to release. Use measured traces to fix actual non-dialogue stalls; warm required resources at startup and spatially index frequently queried terrain. Confirm fluid movement immediately after every dialogue close.
3. **Outskirts: a recognizable inhabited road.** Keep the blue knight separated from stone and sky; restore landmark silhouettes and the visual hierarchy of camp, survey, counterweight and bell tower. Give Rowan, Mara, Vey and Olan their existing individual designs and work beats. Use a few meaningful moving details—chart corner, cloth, warm fire, rope tension—at those landmarks. Keep long travel stretches readable rather than filling them with repeating towers and haze.
4. **Black Woods: distinct layers and practical light.** Restore the source's dark canopy, midground trunks, distant forest and pale moon with stronger depth separation. Make Elsie's pot, the working lamp, pale resin pods and Bram's return light recognizable at gameplay scale. Warm amber should reveal the intended nearby route while thorns, false branches and hostile tells retain readable silhouettes. Add ferns, roots and restrained motes where they reinforce existing landmarks; keep canopy jumps and landings clear.
5. **Read the next action from the world.** Reuse the current quests. Show one objective, the actual bound action and a directional cue when needed; separate success from the next instruction. Carry the same lantern visibly, show actual gear state, and keep a completion/return cue until acted upon. Avoid coordinates and implementation terminology in player-facing prompts.
6. **Improve movement presentation without changing reach.** Match base camera framing, speed perception, landing cues and attack anticipation. Use restrained interpolation and camera easing with predictable vertical look; reduce shake and particle density that hide collision edges. Keep movement constants and route geometry fixed while assessing presentation.
7. **Broaden fidelity evidence.** Compare normal controls and the actual base engine over slopes, one-way ledges, edges, resin impulses, combat, blood, falls and recovery, quest interruptions, reward/retry and saved Continue. Test with voices off and sound off. Keep native-only route tests, but label their narrower purpose. Collect first-minute and matched-pose screenshots and have Isaac play the result before any new voice expenditure.

Suggested review gates: (a) the knight and first minute visibly match the intended identity; (b) no unexplained stalls on the measured route; (c) surviving falls recover locally and locked dash stays silent; (d) all three existing opening/forest quest flows are clear without external instructions; (e) base and native comparative tests cover the affected mechanics. Only then consider additional decorative polish. Any later implementation remains a separate approval.
