# Bladefall and Felix audit fixes — November 10, 2026

This change set addresses the confirmed issues and measured opportunities in [the package audit](PACKAGE-AUDIT-2026-11-10.md). The rebuilt web, macOS, Windows and Android packages are local candidates. The existing public releases are separate.

| Audit finding | Change and verification |
| --- | --- |
| Felix kept playing when focus was lost | Focus loss and application backgrounding pause the game and release touch input. The regression test verifies the world does not advance while paused. Bladefall now handles application backgrounding as well. Both web wrappers pause when the page is hidden or the rotate overlay covers play. |
| A rejected checkpoint could be overwritten | Both games move the original to a uniquely named recovery file before writing a replacement. If the move fails, automatic saving stops for that run and the player sees a message. Tests verify byte-for-byte preservation and a valid fresh checkpoint. Existing save envelopes and compatible fingerprint migrations are retained. |
| Cold web loads could time out despite receiving data | Startup now times out on inactivity. The loader streams each compressed part into the final asset buffer, reports actual bytes received, checks sizes and verifies the final SHA-256. Chromium at 3 Mbps completed cold starts in approximately 147 seconds (Bladefall) and 162 seconds (Felix), both longer than the old 120-second cutoff. |
| Felix saved full snapshots every two seconds | Ordinary snapshots are spaced ten seconds apart. Room, phase, checkpoint, death and progress changes still trigger saves, as do explicit pause/exit and transfer actions at safe boundaries. The individual write can still cost a frame; this reduces its frequency. |
| Bladefall eagerly constructed every world | Normal startup constructs Outskirts only. Later worlds are created on selection and retain their live state when revisited. In a local headless probe, initial construction fell from about 7.3 seconds for nine worlds to about 1.1 seconds for one world. This is a startup sample on this Mac, not a device-wide benchmark. |
| Repeated terrain refreshes and eager audio loads | Both games refresh only affected road tiles as passages change, with a full refresh on reset. Unused scores no longer warm at startup; active tracks load when needed. Background machinery still advances deterministically and the soundtracks remain packaged. |
| Both Mac ZIPs bundled the editor | The bundles now use the matching official Godot release runtime and verify both `arm64` and `x86_64` before signing. Bladefall fell from 189.9 to 98.4 MiB; Felix from 198.1 to 106.7 MiB. See [Godot's export templates](https://github.com/godotengine/godot-builds/releases/tag/4.5.1-stable). |
| Bladefall Android credits and build validation | The APK contains both the Godot license and audio credits. The build checks the signed APK and required entries; native build scripts reject logged engine errors even if the engine exits zero. |

The regression and journey suites exercised ordinary save/restore, incompatible or corrupt checkpoints, continued route selection, passage reveals, Felix's three connected chapters and all six Felix challenge routes. Bladefall's passage scenes were rendered in normal and reduced-motion modes. Both desktop browser save round trips passed. Phone-sized Chromium and WebKit sessions played, rotated and exported a checkpoint after the rotation paused the game. A separate stalled-transfer check verified that both wrappers still offer Retry.

Both signed APKs installed and launched on the Android emulator, and Bladefall's exported APK assets passed the save, unlock and connected-route suites. The Windows ZIPs were verified and their game packs exercised on macOS. The Mac apps were signed locally and launched with the release runtime. Local archive hashes are in `exports/LOCAL-BUILD-SHA256SUMS.txt` in each game. Recovery copies are kept alongside the active checkpoint, with a `.recovery-…` suffix.

The highest-value remaining manual checks are real-phone thumb comfort and sustained performance in late Woods/Causeway, native Windows launch/controller behavior, and quit/resume around late story handoffs. No physical phone or Windows PC was available for this run. Mac notarization and Windows signing are separate release tasks. See the audit for the specific rooms and expected results.
