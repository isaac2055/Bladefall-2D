# Test flags and camera inspection — 7.330

The existing switch remains five clicks on Screen shake in Assist & options. With test mode on, I places or replaces a cyan checkpoint flag at the knight. R, the controller retry button, and Pause → Retry restore that flag’s complete current-room simulation: position, momentum, dash state, phase, devices and clocks. It works across room transitions within the same chapter/world. Deaths and run statistics are retained; restored testing invalidates timed/perfect runs. Ordinary automatic death respawns are unchanged. A new world/chapter or switching test mode off clears the flag; Clear test flag restores the normal retry behavior. Flags are temporary for the current loaded game, not durable Core save lanterns. Outside test mode, I keeps its original blade binding.

Mouse dragging on the play canvas pans both axes. After release, the scene stays frozen at that camera position so screenshots are stable. Follow knight · resume returns the camera and simulation to normal. A click without dragging does not pause. Keyboard shortcuts while typing/rebinding, menus, route demonstrations and touch gestures do not trigger these aids. Test mode off removes all temporary flags/panning. The connected Climb renders the inspected terrain using the held world camera; room-bank/ordinary rooms use the same feature with room bounds.

Implementation: `public/bladefall-pcore-test-tools.js`, integrated with `bladefall-pcore-view.js` and `bladefall-climb-view.js`. Snapshot cloning preserves entity graph references, carried items, mirrored tile data, and tide callbacks. Climb checkpoint context restores quest/entrance state, and camera reset prevents easing back from a distant inspection position. This module is included in Precision, the service worker and offline mirror.

Verification: `node scripts/climb/test-tools-check.mjs` exercises real DOM key/pointer handlers and the actual five-click switch, visible flag drawing, R/repeated restoration, 134 native bank scene snapshots, tide/gravity cases, deterministic device clocks, room transitions, mouse scaling/freeze/follow, inactive-mode/touch/menu guards, and actual Climb camera/terrain rendering. `cores-check.mjs`, existing finale simulation proofs, cloud-review tests and the asset checks still pass. These are native simulation and DOM/canvas-call tests; live browser testing was unavailable/denied. No APK rebuild or API Worker change is needed.
